## 2026-10-07 · v1.2.0

**动因**（用户指令）：结合 GitHub 上会议纪要类技能的全部优点升级本技能。调研了四个参照（GitHub 原文）：zrosenfield/sharepoint-ai-skills `decision-log`（决策记录提取）、alapha888/agent-skills-en `meeting-notes`（极简纪要）、tomique34/claude-skill-creator `meeting-notes-to-action-items`（行动项转换）、zhaozhaozhiyi/XIAOCHUANGx `skill-mm-summary`（中文纪要）。逐项吸收后落地 8 处改动，五章节骨架与出稿链不变：

1. **结论先行**（源自 meeting-notes「Bottom line」）：「会议总结」首段 ≤3 行概括本次会议最终定了什么，未参会者读一段即掌握全局。
2. **决策肯定句式**（源自 meeting-notes 反模式）：写「已决定 X」不写「讨论了 X」；写入模板、工作流程第 3 步与质量自检三处。
3. **重大决策依据链 + 异议如实记录**（源自 decision-log 的 Decision Record 八字段，取其轻）：资源投入/方向变更类决策可展开背景、备选方案、理由；反对与保留意见记「谁提出、什么顾虑、最终处理」，不因决策已通过而略去。
4. **待定与开放问题子块**（源自 decision-log Pending Decisions + meeting-notes Open Questions）：未决事项说清「待决什么、卡在哪、谁推进、有无时限」；跟进问题与任务分离，不混入待办表。
5. **待办识别线索表**（源自 meeting-notes-to-action-items 语言模式表，中文化）：口语句式 → 字段映射（「X 会跟进」→责任人等）；疑问句式显式路由到待定与开放问题块。
6. **待办标题规范 + 优先级判定线索**（源自 meeting-notes-to-action-items）：动词开头、具体可执行；阻塞→高、未标注→默认中并注记、锦上添花→低，只取原文语言线索不自行加权。
7. **不完整记录标注**（源自 decision-log 的 Partial transcripts）：转写稿截断/缺失时在基本信息区显著标注「原始记录不完整，结论可能有偏差」。
8. **质量自检清单 + 反模式清单 + 长度控制**（源自 meeting-notes 自检四问/反模式与 ≤1/3 长度规则）：新增两节；工作流程第 6 步改为按清单逐项核对；长度约束进「约束」节（转写稿场景 ≤1/3，短记录按自然长度）。

**未采纳**（与公文纪要定位或本机交付链不符）：QA 问答对章节（skill-mm-summary）、JIRA/Trello/API 脚本通道（tomique34，与 docx 出稿链冲突）、决策记录独立成档（decision-log，破坏五章节既有格式）、说话人映射先问后做（decision-log，本技能「推定+待确认」策略更轻量，保留本地策略）。

**回滚点**：`backups/SKILL.v1.1.0.bak.md`（升级前全文备份，与 v1.1.0 CHANGELOG 对应）。

## 2026-10-07 · v1.2.1

**动因**（用户追问「还有可优化的地方吗」）：派 critic 子代理对 v1.2.0 做对抗式审查，裁定「有条件通过」。修复其列出的 2 条 P0 硬冲突（均为 v1.2.0 引入）、3 条 P1 边界模糊与 6 处零成本一致性项：

1. **P0-1 无主待办冲突**：v1.2.0 反模式「没有责任人的事不算待办事项」与既有「缺项标待定」正面冲突。现口径统一：无主任务保留在待办表、责任人标「待定（会上未指定）」，反模式条目改为「不得臆造责任人，也不得因无主而删除任务」。
2. **P0-2 优先级判定冲突**：旧条款「优先级未标注填待定」与 v1.2.0 新增「未标注默认为中并注记」同节矛盾。现旧条款从「填待定」清单移出优先级，显式指向「优先级判定」规则。
3. **P1-1 标记词定义**：新增「待定/待确认」边界定义进「约束」节（待定=悬而未决的状态；待确认=缺失或无法溯源的信息），基本信息缺失场景统一为「待确认」（原 v1.1.0 起两处混用）。
4. **P1-2 长度裁决**：≤1/3 与「不删关键信息」补裁决规则——保留重要信息优先于压缩比例，确因信息密度超限的允许超限并说明原因；口径明确为不含基本信息区与待办表格；质量自检同步。
5. **P1-3 章节划界**：决策类条目（含状态、依据、异议）唯一归「会议总结」并豁免「议题不重复」规则，核心要点只收非决策类事实与数字——消除「决策既是关键结论又归总结」的必然重复。
6. **零成本一致性项**：流程第 3 步「展开依据链」对齐为「可展开」；识别线索表补负向过滤（表态句不提取）与第一人称承诺映射；待办节补无待办出口（保留标题注明「未形成行动事项」）；不完整记录标注适用面扩至笔记与聊天记录片段；「出稿四步链」更名「出稿链」消名实不符；触发分支补口语变体；`%USERPROFILE%` 括注去硬编码；「见上」指路规范为「见〈章节名〉」。

**未处理（critic P2-5，留观）**：新增两节与「约束」节的规则重复面——prompt 场景下适度重复有强化作用，待真实使用检验是否造成执行漂移再决定是否收敛。

**动因**（用户追问「GitHub 上还有没有更多可参考的」）：扩大调研面二轮——tldr-recap 全文+其 summary-guidelines.md、anthropics/skills 官方仓库、76k star awesome-claude-skills 清单全量 meeting 条目、standup/1on1/retro 垂直搜索。结论：官方与清单无新增提炼纪律（均为 API 适配器/沟通教练/会前准备类），真正增量集中在 tldr-recap 双文档，吸收 6 条新纪律+示例对照实践：

1. **说话人一致性核验**（tldr-recap「Inspect speaker attribution before trusting it」）：推定后查合并/拆分/误归属迹象，存疑则标注不静默采用；无法推定时可摘录典型发言请用户确认（多轮场景），不在场退回待确认——补进转写稿处理第 1 条。
2. **个人建议≠决议**（tldr-recap「One person's advice is not a decision unless others accepted it」）：未获他人接受为共同计划的个人建议归会议内容并归属发言人，防单人意见升格为集体决策——补进会议总结决策判定。
3. **措辞强度对齐**（tldr-recap「Match the strength of the wording」）：「可以考虑/尽量/条件允许的话」不升格为确定任务，工作量举例不是任务分配——补进识别线索负向过滤。
4. **请求方向核对**（tldr-recap「if A asks B and B hands it back, A owns it」）：A 请 B、B 推回 A，责任人是 A——补进识别线索负向过滤。
5. **来源可信度注记扩展**（tldr-recap「source note」）：说话人标签靠推定、转写破损严重同样在基本信息区加注——并入不完整记录条。
6. **用户强调指令优先**（tldr-recap「When the user supplies a focus instruction」）：用户强调要求优先满足，但决策与待办义务不减——补进输入来源处理第 3 条。
7. **最小示例文件**（tldr-recap 例文对照实践）：新增 `references/example-minimal.md`（源记录→成稿对照+规则对照五条），SKILL.md 输出模板节末回指。
